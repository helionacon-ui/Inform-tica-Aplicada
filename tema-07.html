UD2 Programación en C · Tema 7

Abstracción funcional: funciones, paso de parámetros, recursividad y punteros

UD2 Programación en CProblemas en C

Desde cero

Objetivo: Diseñar programas modulares a partir de un diagrama de estructura, declarar, definir e invocar funciones, pasar parámetros por valor y por referencia con punteros, usar recursividad y entender la memoria de un programa en ejecución.

Abstracción funcional: diseño descendente; un problema se descompone en módulos (diagrama de estructura) que serán funciones: una función hace una sola tarea, alta cohesión, bajo acoplamiento. Función: bloque con nombre que acepta valores de entrada y produce (opcionalmente) un valor de salida; caja negra reutilizable; toda aplicación tiene main; bibliotecas (<math.h>, <stdio.h>).

Declaración (prototipo: tipo, nombre y tipos de parámetros, long cubo(int);; obligatoria si se llama antes de definirla o está en otro archivo), definición (el código) e invocación (cubo(8)). Parámetros formales (en la declaración) y reales (en la llamada): mismo número, tipo y orden. Flujo de ejecución: empieza en main; cada llamada salta a la función y al terminar vuelve al punto de la llamada.

Paso de parámetros: por valor (copia; seguro; la función no modifica el original; ineficiente con datos grandes) y por referencia (se pasa la dirección; la función lee y escribe el original: parámetro de entrada/salida; eficiente pero exige cuidado). En C los vectores van por referencia siempre; para el resto se usan punteros: void f(int *v1, int v2){*v1=30; v2=50;} llamada con f(&a, b) cambia a y no b. Una función que devuelve varios valores los devuelve por referencia (ecuación de 2.º grado: int ec2(int a,int b,int c,float *r1,float *r2)).

Memoria de un programa (run-time storage): código, datos estáticos (globales y static), pila (stack: un registro de activación o stack frame por cada función en ejecución con parámetros, dirección de retorno, puntero al frame del invocador, valor de retorno y variables locales; se apila al llamar y se desapila con return) y montículo (heap: memoria dinámica con malloc/free, gestionada por el programador). Variables locales en la pila; globales en datos estáticos (se evitan: ocultación de datos).

Recursividad: una función se llama a sí misma; caso base no recursivo, llamada con un problema más pequeño que converge al caso base; más memoria de pila y tiempo, pero más natural (factorial, Fibonacci, potencia, suma de dígitos). Todo recursivo tiene versión iterativa, no al revés… (según los apuntes: «todo problema recursivo se puede resolver con bucles, pero no viceversa»). Punteros: variable que guarda la dirección de otra; int *p = &x;; & dirección, * contenido; tienen tipo; aritmética: p++ avanza un elemento; un vector es un puntero a su primer elemento (v[i] ≡ *(v+i)); deben inicializarse; malloc devuelve un puntero a memoria del montículo.

Lo que tienes que saber

  • Prototipo / definición / llamada: double area(double); … double area(double r){return PI*r*r;} … a = area(2.5);
  • Salida por referencia: void leer(double *r){ scanf(" %lf", r); } y llamada leer(&radio); (dentro de la función r ya es la dirección: no se pone &).
  • Vectores: void f(int v[], int n) o int *v; matrices int m[][TAM].
  • Factorial recursivo: long fact(long n){ return n==0 ? 1 : n*fact(n-1); }; Fibonacci fib(n)=fib(n-1)+fib(n-2) con fib(0)=0, fib(1)=1.
  • Punteros: int x=2,*y=&x; *y=5; ⇒ x vale 5. *++p avanza y lee; *p++ lee y avanza; (*p)++ incrementa el contenido.
  • Memoria dinámica: v=(int*)malloc(n*sizeof(int)); if(v==NULL)…; free(v);

Cómo se resuelve

  1. Del diagrama de estructura saca el prototipo: entradas → parámetros por valor; salidas → return si es una, punteros si son varias; vectores siempre por referencia.
  2. En la llamada pon & delante de las variables que la función debe rellenar (salvo vectores y variables que ya sean punteros).
  3. Dentro de la función usa *p para leer/escribir el valor apuntado y p directamente en scanf.
  4. Recursión: escribe primero el caso base y comprueba que cada llamada reduce el problema.

Trampas típicas

  • Olvidar & en la llamada o poner & dentro de la función en scanf(" %lf", &r) cuando r ya es puntero.
  • Devolver con return un valor que el diagrama pide por referencia (o al revés).
  • Usar variables globales para comunicar funciones.
  • Recursión sin caso base: desbordamiento de pila.

Problema tipo

Enunciado

(Problema de examen: Bolzano) Raíz de un polinomio por bisección: validar_intervalo devuelve 0 si f(a)·f(b) < 0, −1 si no y −2 si un extremo ya es raíz; encontrar_raiz parte el intervalo por la mitad hasta |f(m)| < PRECISION o MAX_INTENTOS y devuelve la raíz por referencia; completa main con el switch.

✓Ver solución paso a paso
#include <stdio.h>
#include <math.h>
#define MAX_INTENTOS 1000
#define PRECISION 0.000001
#define MAXIMO_GRADO 100
void leer_coeficientes(int g, double *c);
void leer_intervalo(double *a, double *b);
short validar_intervalo(double a, double b, double c[], short g);
short encontrar_raiz(double *raiz, double a, double b, double c[], short g);
double evalua(double x, double c[], short g);

int main(void) {
    short grado, cumple, encontro;
    double a, b, raiz, coefs[MAXIMO_GRADO];
    printf("Grado del polinomio (0 para salir): ");
    scanf("%hd", &grado);
    if (grado <= 0) return 0;
    leer_coeficientes(grado, coefs);
    leer_intervalo(&a, &b);
    cumple = validar_intervalo(a, b, coefs, grado);
    switch (cumple) {
        case 0:
            encontro = encontrar_raiz(&raiz, a, b, coefs, grado);
            if (encontro) printf("Raiz en x = %lf\n", raiz);
            else printf("No se alcanzo la precision en %d intentos\n", MAX_INTENTOS);
            break;
        case -1: printf("f(a) y f(b) tienen el mismo signo: Bolzano no asegura raiz\n"); break;
        case -2: printf("Uno de los extremos ya es raiz\n"); break;
    }
    return 0;
}
double evalua(double x, double c[], short g) {       /* Horner */
    double r = c[g]; int i;
    for (i = g - 1; i >= 0; i--) r = r * x + c[i];
    return r;
}
void leer_coeficientes(int g, double *c) {
    int i;
    for (i = 0; i <= g; i++) { printf("Coeficiente de x^%d: ", i); scanf(" %lf", &c[i]); }
}
void leer_intervalo(double *a, double *b) {
    do { printf("a: "); scanf(" %lf", a); printf("b: "); scanf(" %lf", b); } while (*a >= *b);
}
short validar_intervalo(double a, double b, double c[], short g) {
    double ra = evalua(a, c, g), rb = evalua(b, c, g);
    if (ra == 0 || rb == 0) return -2;
    if (ra * rb > 0) return -1;
    return 0;
}
short encontrar_raiz(double *raiz, double a, double b, double c[], short g) {
    int intentos = 0;
    double m, fm, fa = evalua(a, c, g);
    do {
        m = (a + b) / 2;
        fm = evalua(m, c, g);
        if (fa * fm < 0) b = m; else { a = m; fa = fm; }
        intentos++;
    } while (fabs(fm) > PRECISION && intentos < MAX_INTENTOS);
    *raiz = m;
    return fabs(fm) <= PRECISION;
}

Probado con x² + 4x − 6 en [1, 5]: raíz 1,162278 (exacta \(-2+\sqrt{10}\)). evalua usa Horner para no llamar a pow.

1¿Qué imprime fun1(&v1,v2) con void fun1(int *v1,int v2){*v1=30; v2=50;} si v1=10, v2=20?

v1=30, v2=20: v1 va por referencia y v2 por valor.

2Test: ¿qué llamada hace que b valga 3.0 con void f1(double *b,int c){*b*=c;}, b=1.5, a[5]={1,2,3,4,5}?

f1(&b, a[1]); (1.5 × 2).

3Registro de activación: ¿qué afirmación es falsa?

Que se almacena en el montículo: se apila en la pila (stack) en cada llamada y se desapila al terminar; guarda parámetros, dirección de retorno, locales y punteros al invocador; puede agotar la pila con recursiones profundas.

4Escribe int suma_digitos(int n) recursiva.

if (n < 10) return n; return n%10 + suma_digitos(n/10);

5Diferencia entre parámetros formales y reales.

Formales: los de la declaración/definición; reales: los de la llamada. Deben coincidir en número, tipo y orden.
