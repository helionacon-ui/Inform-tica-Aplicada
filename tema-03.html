UD2 Programación en C · Tema 3

Programación estructurada y algoritmia

UD2 Programación en CProblemas en C

Desde cero

Objetivo: Definir programa y algoritmo, distinguir paradigmas y niveles de lenguaje, aplicar las reglas de la programación estructurada, leer flujogramas y diagramas de estructura, y conocer léxico, sintaxis y semántica de C.

Complejidad y abstracción: el software suma la complejidad del problema y la del computador; la abstracción separa lo esencial de lo accesorio: abstracción de datos (significado de los bits: tipos) y de control (estructuras de control y funciones). Programa = secuencia finita de instrucciones = algoritmo + datos. Algoritmo: termina en un número finito de pasos, cada paso definido con precisión, al menos una salida (entradas opcionales), cada operación en tiempo finito.

Paradigmas: imperativo y estructurado (C: variable como estado, asignación, funciones), orientado a objetos (C++, Java, Python), funcional (LISP), lógico (Prolog), declarativo (SQL). Lenguajes de alto y bajo nivel; compilados (C: el compilador genera ejecutable) e interpretados (Basic, Java en la JVM). Herramientas: editor, compilador, enlazador, depurador (Code::Blocks, Dev-C++ en prácticas).

Reglas de la programación estructurada: secuencialidad, selección, repetición y apilamiento/anidamiento (cualquier acción se sustituye por una secuencia, selección o repetición). En C: yuxtaposición; if, switch, ?:; for, while, do-while; bloques { }. break y continue rompen el principio de una única salida (equivalente con bandera salir en la condición). Saltos que ejecuta la CPU: incondicional, condicional, bucle, llamada/retorno de subrutina, parada.

Léxico, sintaxis, semántica: léxico de C = comentarios, identificadores, palabras reservadas, separadores, literales, operadores; sentencia simple (termina en ;), compuesta ({ }), expresión. Flujograma: inicio/fin, proceso, decisión (rombo), E/S, con los esquemas de secuencia, bifurcación simple/compuesta y repetición (while/for y do-while). Diagrama de estructura (diseño descendente): cajas = módulos/funciones, jerarquía de llamadas y flechas con los datos que entran y salen (lo que se pide leer en todos los problemas de examen; independiente del lenguaje). Módulos con alta cohesión y bajo acoplamiento.

Explicación ampliada

Del problema al algoritmo

Un algoritmo es una secuencia finita y ordenada de pasos sin ambigüedad que resuelve un problema. Antes de escribir código conviene: (1) entender qué entra y qué debe salir, (2) resolver a mano un caso pequeño, (3) describir los pasos en pseudocódigo o diagrama de flujo y (4) traducir a C.

La programación estructurada demuestra que basta combinar tres estructuras: secuencia, selección (si/si no) e iteración (mientras). Evita los saltos arbitrarios, lo que hace el programa legible y comprobable.

Traza de un algoritmo y su coste

La herramienta que más puntos da en examen es la traza: una tabla donde, línea a línea, anotas el valor de cada variable. Si dominas la traza, puedes predecir la salida de cualquier programa y encontrar sus errores.

El coste se estima contando cuántas veces se ejecuta la operación más repetida. Un bucle simple de \(n\) vueltas hace \(n\) operaciones; dos bucles anidados, \(n^2\); un bucle que divide por 2 en cada vuelta, \(\log_2n\). Aunque el computador sea rápido, pasar de \(n\) a \(n^2\) con \(n=10^6\) es la diferencia entre un segundo y días.

Desarrollo teórico a fondo

1Algoritmo: qué se pide de él

Idea clave. un algoritmo es una secuencia finita, precisa y no ambigua de pasos que resuelve un problema y termina.
  • Entrada, proceso y salida: antes de programar, decide qué datos llegan, qué hay que calcular y qué se devuelve.
  • Representaciones: pseudocódigo y diagramas de flujo.

2Programación estructurada

Todo programa puede escribirse con tres estructuras básicas:

  • Secuencia: una instrucción detrás de otra.
  • Selección: elegir un camino según una condición (\(\mathrm{if}\)).
  • Repetición: repetir mientras se cumpla una condición (\(\mathrm{while}\), \(\mathrm{for}\)).

Evita saltos arbitrarios (\(\mathrm{goto}\)): el flujo es más fácil de seguir y de comprobar.

∴Diseño descendente: cómo atacar un problema grande
  1. Describe el problema en una frase.
  2. Divídelo en subproblemas más pequeños.
  3. Repite con cada subproblema hasta que cada uno sea trivial.
  4. Cada subproblema se convierte en una función.

Traza a mano con un ejemplo pequeño (tabla de valores de las variables paso a paso). Es la mejor manera de encontrar errores lógicos antes de ejecutar.

Lo que tienes que saber

  • Programa = algoritmo + datos. Propiedades del algoritmo: finito, preciso, ≥ 1 salida, cada paso en tiempo finito.
  • Estructuras de control de C (siete): if, if-else, switch, while, do-while, for (+ break/continue).
  • Equivalente de break: int salir=0; while(cond && !salir){ … if(c2) salir=1; else {…} }.
  • Diagrama de estructura: módulo superior invoca a los inferiores; flecha con círculo blanco = dato, círculo negro = control; parámetros de salida ⇒ en C devolución por referencia (punteros) o return.

Cómo se resuelve

  1. Ante un diagrama de estructura: cuenta cajas = funciones; las flechas hacia abajo son parámetros de entrada, hacia arriba valores devueltos (return o punteros).
  2. Escribe primero los prototipos, luego main con las llamadas en el orden del diagrama, y por último cada función.
  3. Flujograma → código: rombo = if/while; mira si la condición se evalúa antes (while) o después (do-while).

Trampas típicas

  • Confundir diagrama de estructura (funciones) con flujograma (flujo dentro de una función) o con un diagrama ER (bases de datos).
  • Decir que un algoritmo necesita entradas: no; necesita al menos una salida.

Problema tipo

Enunciado

(Test de examen) «Con respecto al diagrama de estructura: a) es muy utilizado en la POO; b) permite diseñar una base de datos; c) cambia la notación según el lenguaje; d) todas son falsas.» Y: «¿Cuál es falsa sobre el concepto de algoritmo? … c) debe tener al menos una salida y al menos una entrada; d) debe tener al menos una salida pero puede no tener ninguna entrada.»

✓Ver solución paso a paso

El diagrama de estructura es propio del diseño estructurado, no de la POO ni de las BD, y su notación no depende del lenguaje: d. Sobre el algoritmo, la falsa es c (no hay restricción sobre las entradas).

Ejercicios resueltos

Intenta cada uno antes de desplegar la solución.

Ejercicio 1 · Algoritmo de Euclides

Haz la traza del algoritmo de Euclides para el máximo común divisor de 48 y 18:

int a = 48, b = 18;
while (b != 0) {
  int r = a % b;
  printf("a=%d b=%d r=%d\n", a, b, r);
  a = b;
  b = r;
}
printf("mcd=%d\n", a);
✓Ver solución paso a paso

Salida del programa (cada fila es una vuelta del bucle):

a=48 b=18 r=12
a=18 b=12 r=6
a=12 b=6 r=0
mcd=6

El resto se va haciendo menor hasta llegar a 0, y el último divisor no nulo es el mcd = 6.

Ejercicio 2 · Suma de las cifras

Predice la salida de este programa para \(n=4729\):

int n = 4729, s = 0;
while (n > 0) {
  s += n % 10;
  n /= 10;
  printf("s=%d n=%d\n", s, n);
}
✓Ver solución paso a paso

Traza: se extrae la cifra de unidades con n%10 y se descarta con n/=10.

s=9 n=472
s=11 n=47
s=18 n=4
s=22 n=0

La suma es 9+2+7+4 = 22. El mismo patrón sirve para contar dígitos o invertir un número.

Ejercicio 3 · Coste de bucles anidados

¿Cuántas veces se ejecuta el printf en for(i=0;i<n;i++) for(j=0;j<=i;j++) printf("*"); para \(n=5\)? ¿Y en general?

✓Ver solución paso a paso

Para cada \(i\), el bucle interno hace \(i+1\) vueltas: 1, 2, 3, 4, 5, con un total de 15 asteriscos (un triángulo).

En general \(1+2+\dots+n=\dfrac{n(n+1)}2\), es decir, el coste crece como \(n^2/2\): cuadrático.

1Reglas de la programación estructurada y su correspondencia en C.

Secuencialidad (sentencias una tras otra), selección (if, switch, ?:), repetición (for, while, do-while) y apilamiento/anidamiento (bloques { }).

2¿Por qué break y continue rompen la programación estructurada?

Crean una salida del bucle distinta de la definida en su condición. Se sustituyen por una bandera en la condición (salir) y un else que evita el resto del cuerpo.

3Léxico, sintaxis y semántica.

Léxico: símbolos del lenguaje (identificadores, palabras reservadas, literales, operadores, separadores, comentarios). Sintaxis: reglas para formar sentencias correctas. Semántica: significado de las sentencias (qué hace el computador).

4¿Qué dota de significado a las secuencias de bits?

La abstracción de datos (los tipos de datos).
