Bases de datos relacionales y SQL

UD3 Sistemas operativos y bases de datosTeoría (test)

Desde cero

Objetivo: Explicar qué es una base de datos y un SGBD, los niveles de abstracción, los modelos de datos, el diagrama entidad-relación y su paso a tablas, claves primarias y ajenas con integridad referencial, y escribir consultas SQL (SELECT, JOIN, subconsultas, agregados) en SQLite.

Base de datos: colección estructurada de datos que refleja objetos, relaciones y restricciones de una parcela del mundo real. SGBD: software de propósito general para crear y manipular BD (MySQL, Oracle, PostgreSQL, SQL Server, SQLite en prácticas). Propiedad esencial: independencia de datos gracias a los tres niveles: físico (implementación), lógico (esquema: tablas), externo (vistas parciales para grupos de usuarios). Modelo de datos: conceptos y reglas para estructurar los datos (estáticas y dinámicas); primitivos (ficheros), jerárquico, en red y relacional (tablas y lenguajes declarativos).

Diagrama entidad-relación: (Chen, 1976): entidades (rectángulo), atributos (óvalo, identificador subrayado), relaciones (rombo) con cardinalidades 1:1, 1:N, N:M, y restricciones. Paso al relacional: cada entidad → tabla con su clave primaria; relación 1:N → la clave del lado 1 pasa como clave ajena al lado N; relación N:M → tabla nueva con las dos claves (ciclista-etapa, concejal-regidor). Clave primaria: atributos que identifican unívocamente cada tupla (no nula, única, mínima). Clave ajena: atributos de una tabla que son clave primaria de otra; la integridad referencial exige que sus valores existan en la tabla referenciada; el SGBD rechaza las actualizaciones que la violen o actúa según ON DELETE / ON UPDATE (CASCADE borra o cambia en cadena, NO ACTION/RESTRICT impide la operación, SET NULL).

SQL: (declarativo): CREATE TABLE con tipos (INT, VARCHAR, DATE), PRIMARY KEY, FOREIGN KEY … REFERENCES; INSERT, UPDATE, DELETE; SELECT campos FROM tablas WHERE condición; joins por igualdad de claves (FROM ciclista C, equipo E WHERE C.nomeq=E.nomeq o JOIN … ON); DISTINCT; ORDER BY; agregados COUNT, SUM, AVG, MIN, MAX con GROUP BY y HAVING; subconsultas con IN, NOT IN, EXISTS, NOT EXISTS y comparación con un agregado (WHERE altura > (SELECT AVG(altura) FROM puerto)). Base de ejemplo de prácticas: EQUIPO(nomeq, director), CICLISTA(dorsal, nombre, edad, nomeq→EQUIPO), ETAPA(netapa, km, salida, llegada, dorsal→CICLISTA), PUERTO(nompuerto, altura, categoría, pendiente, netapa→ETAPA, dorsal→CICLISTA).

Explicación ampliada

Pensar en tablas: modelo relacional

Una base de datos relacional guarda la información en tablas (filas = registros, columnas = atributos). La clave primaria identifica cada fila sin repeticiones; una clave foránea es un atributo que apunta a la clave primaria de otra tabla y expresa la relación entre ambas (un puerto lo gana un ciclista).

La integridad referencial impide referenciar filas que no existen; al borrar el padre, la regla puede ser CASCADE (borra hijos) o NO ACTION (lo prohíbe si hay hijos).

SELECT: el patrón en cinco cláusulas

Casi toda consulta de examen sigue el esqueleto SELECT columnas FROM tablas WHERE condiciones GROUP BY agrupación HAVING condición de grupo. Dos tablas en el FROM se enlazan con una condición del WHERE sobre la clave foránea (join); sin ella sale el producto cartesiano.

Subconsultas: para comparar con agregados (> (SELECT AVG(…))) y para negación (NOT IN). Las funciones de agregado (COUNT, SUM, AVG, MAX, MIN) colapsan filas; WHERE filtra filas antes de agrupar y HAVING, grupos después.

Desarrollo teórico a fondo

1El modelo relacional

  • Los datos se organizan en tablas (relaciones): filas = registros, columnas = atributos.
  • Clave primaria: identifica cada fila, sin repetirse ni ser nula.
  • Clave foránea: atributo que apunta a la clave primaria de otra tabla; así se relacionan.

Relaciones entre entidades: 1:N (un cliente, muchos pedidos) se resuelve con una clave foránea en el lado «N»; N:M exige una tabla intermedia.

2SQL: las consultas, en el orden en que se piensan

  1. FROM: de qué tabla(s) (y JOIN para unirlas).
  2. WHERE: qué filas se quedan.
  3. GROUP BY: agrupar, con funciones como COUNT, SUM, AVG, MAX, MIN.
  4. HAVING: filtrar los grupos.
  5. SELECT: qué columnas mostrar. ORDER BY: orden.
Cuidado. WHERE filtra filas antes de agrupar; HAVING filtra grupos después. No se pueden usar funciones de agregación en WHERE.
∴JOIN: unir tablas
  • INNER JOIN: solo las filas que tienen pareja en ambas tablas.
  • LEFT JOIN: todas las de la izquierda, con NULL si no hay pareja.

Ejemplo: SELECT c.nombre, COUNT(p.id) FROM cliente c LEFT JOIN pedido p ON p.cliente = c.id GROUP BY c.nombre; cuenta los pedidos de cada cliente, incluidos los que no tienen ninguno.

3Normalización

Idea clave. organizar las tablas para no repetir datos y evitar anomalías al insertar, borrar o modificar.
  • 1FN: valores atómicos (sin listas dentro de una celda).
  • 2FN: todo atributo depende de toda la clave.
  • 3FN: ningún atributo depende de otro atributo que no sea clave.

Lo que tienes que saber

  • Join: SELECT P.nompuerto, P.categoria FROM puerto P, ciclista C WHERE P.dorsal = C.dorsal AND C.nomeq = 'Banesto';
  • Negación: SELECT salida, netapa FROM etapa WHERE netapa NOT IN (SELECT netapa FROM puerto);
  • Agregado con subconsulta: SELECT nompuerto FROM puerto WHERE altura > (SELECT AVG(altura) FROM puerto);
  • Agrupar: SELECT nomeq, COUNT(*) FROM ciclista GROUP BY nomeq HAVING COUNT(*) > 3;
  • Máximo con join: SELECT C.dorsal, C.nombre FROM ciclista C, puerto P WHERE C.dorsal = P.dorsal AND P.altura = (SELECT MAX(altura) FROM puerto);
  • ON DELETE CASCADE: al borrar el padre se borran los hijos; NO ACTION: se impide el borrado si hay hijos; ON UPDATE CASCADE propaga el nuevo valor.

Cómo se resuelve

  1. Identifica las tablas que contienen los datos pedidos y únelas por las claves ajenas (una condición de igualdad por cada enlace).
  2. «que no tienen» ⇒ NOT IN / NOT EXISTS; «el más/menos» ⇒ subconsulta con MAX/MIN o comparación con AVG; «cuántos por cada» ⇒ GROUP BY.
  3. Integridad: para cada clave ajena mira la cláusula ON DELETE/ON UPDATE y razona tabla por tabla qué se borra, se propaga o se impide.

Trampas típicas

  • Escribir SELECT * WHERE … FROM (el orden es SELECT FROM WHERE).
  • Olvidar la condición de join (producto cartesiano).
  • Usar un agregado en WHERE en vez de en HAVING o en una subconsulta.
  • Decir que la clave primaria puede ser nula o que «referencia» a otra tabla (esa es la ajena).

Problema tipo

Enunciado

(Enunciado tipo del segundo parcial) Con las tablas pueblo(nom_pueblo PK, provincia, codigo_postal, censo), persona(nombre PK, direccion, telefono, edad), legislatura(regidor→persona ON DELETE CASCADE ON UPDATE NO ACTION, municipio→pueblo ON DELETE CASCADE) y equipo_concejales(concejal→persona ON DELETE CASCADE ON UPDATE CASCADE, regidor→persona ON DELETE NO ACTION ON UPDATE NO ACTION): a) ¿qué ocurre al borrar un concejal? b) ¿y al cambiar el nombre a un alcalde? Escribe: 1) regidores con dirección, teléfono y pueblo; 2) pueblos con censo < 1000 sin alcalde; 3) pueblo del alcalde más longevo; 4) cuántos concejales tiene cada alcalde de pueblos de más de 20 000 habitantes.

✓Ver solución paso a paso

a) Borrar la persona que es concejal: en equipo_concejales su fila se borra (CASCADE); si además fuera regidor de alguien, el NO ACTION del campo regidor impide el borrado; si fuera alcalde, su legislatura se borraría (CASCADE). b) Cambiar el nombre de un alcalde: legislatura.regidor es ON UPDATE NO ACTION ⇒ la actualización se rechaza mientras tenga legislatura (y también equipo_concejales.regidor es NO ACTION); solo como concejal se propagaría (CASCADE).

-- 1
SELECT P.nombre, P.direccion, P.telefono, L.municipio
FROM persona P, legislatura L WHERE P.nombre = L.regidor;
-- 2
SELECT nom_pueblo FROM pueblo
WHERE censo < 1000 AND nom_pueblo NOT IN (SELECT municipio FROM legislatura);
-- 3
SELECT L.municipio FROM legislatura L, persona P
WHERE L.regidor = P.nombre
  AND P.edad = (SELECT MAX(P2.edad) FROM persona P2, legislatura L2 WHERE P2.nombre = L2.regidor);
-- 4
SELECT E.regidor, COUNT(*) AS concejales
FROM equipo_concejales E, legislatura L, pueblo PU
WHERE E.regidor = L.regidor AND L.municipio = PU.nom_pueblo AND PU.censo > 20000
GROUP BY E.regidor;

Ejercicios resueltos

Intenta cada uno antes de desplegar la solución.

Ejercicio 1 · Join con condición

Con el esquema
equipo(nomeq PK, director)
ciclista(dorsal PK, nombre, edad, nomeq)
puerto(nompuerto PK, altura, categoria, dorsal FK→ciclista)
escribe la consulta que muestre cada puerto ganado por ciclistas del equipo Banesto, con el nombre del ciclista.

✓Ver solución paso a paso
SELECT P.nompuerto, C.nombre
FROM puerto P, ciclista C
WHERE P.dorsal = C.dorsal
  AND C.nomeq = 'Banesto';

Con los datos de ejemplo devuelve:

Lagos | Indurain
Tourmalet | Delgado

La condición P.dorsal = C.dorsal es el join: sin ella, cada puerto se emparejaría con todos los ciclistas.

Ejercicio 2 · GROUP BY y HAVING

Con el mismo esquema, lista los equipos que tienen al menos 2 ciclistas, con su número.

✓Ver solución paso a paso
SELECT nomeq, COUNT(*)
FROM ciclista
GROUP BY nomeq
HAVING COUNT(*) >= 2;
Banesto | 2
Once | 2

HAVING filtra grupos; no podría ir en el WHERE, porque COUNT(*) aún no existe cuando se filtran las filas.

Ejercicio 3 · Negación con subconsulta

Con el mismo esquema, muestra los ciclistas que no han ganado ningún puerto.

✓Ver solución paso a paso
SELECT nombre
FROM ciclista
WHERE dorsal NOT IN (SELECT dorsal FROM puerto);
Rominger
Zulle

Para «los que no…» no sirve un join sencillo (solo mostraría los que sí tienen); se usa NOT IN o NOT EXISTS. Cuidado: si la subconsulta devolviera algún NULL, NOT IN no devolvería nada.

1Definición y utilidad de las claves primaria y ajena.

Primaria: conjunto mínimo de atributos que identifica unívocamente cada tupla (no nulos, únicos). Ajena: atributos de una tabla que son clave primaria de otra y establecen la asociación; su integridad referencial la comprueba el SGBD. En SQL: PRIMARY KEY y FOREIGN KEY … REFERENCES.

2Prácticas ciclismo: etapas que tienen algún puerto, de tres formas.

Join FROM etapa E, puerto P WHERE P.netapa = E.netapa con DISTINCT; WHERE netapa IN (SELECT netapa FROM puerto); WHERE EXISTS (SELECT * FROM puerto P WHERE P.netapa = E.netapa).
